# 文件分享接口协议

本文定义任务 44 的前后端对接契约，对照当前 `frontend/src/api/shares.ts`、分享页面与现有文件接口编写。当前仓库的分享前端已发起真实请求，分享后端接口尚未实现；以下分享接口的响应和权限规则仍需后端确认并联调。分享 Token 是随机且不可预测的访问凭证；持有有效链接的访客无需登录即可查看和下载分享文件。成功响应直接返回 DTO，不额外包装 `data`；错误沿用 `{ code, message, fields }`。

前端通过 `VITE_API_BASE_URL`（未配置时为 `/api`）请求接口。所有者接口使用带 Bearer Token 的请求客户端，公开接口使用不附带用户 Token 的独立客户端。前端页面链接由浏览器拼接为 `${location.origin}/share/${encodeURIComponent(token)}`，链接指向前端路由 `/share/:token`，不是后端 API 地址；Token 本身即访问凭证，不另设提取码。

## DTO

### `ShareResponse`

```json
{
  "id": "51",
  "token": "opaque-random-token",
  "fileId": "42",
  "fileName": "项目方案.pdf",
  "kind": "file",
  "size": 9017754,
  "createdAt": "2026-09-30T04:00:00Z",
  "expiresAt": "2026-10-07T04:00:00Z",
  "status": "ACTIVE"
}
```

`id` 和 `fileId` 均以十进制字符串传输，避免 JavaScript 整数精度损失。`kind` 与现有后端文件接口和前端类型一致：文件为 `file`，文件夹为 `folder`；当前只允许分享普通文件。前端的图片、视频、音频、文档等分类根据文件名扩展名推断，不作为接口 `kind` 的取值。`status` 为 `ACTIVE` 或 `CANCELLED`，不单独返回 `EXPIRED`；过期状态由前端结合 `expiresAt` 与当前时间判断，服务端访问校验仍以服务端时间为准。`token` 只在认证后的创建及“我的分享”列表响应中提供给所有者，不出现在公开详情响应中。

### `ShareAccessResponse`

```json
{
  "file": {
    "id": "42",
    "name": "项目方案.pdf",
    "kind": "file",
    "size": 9017754,
    "parentId": null,
    "updatedAt": "2026-09-29T06:30:00Z",
    "deletedAt": null
  },
  "expiresAt": "2026-10-07T04:00:00Z"
}
```

`file` 的字段形状与现有文件接口响应一致（包含 `deletedAt`）；有效分享返回的文件应未删除，故 `deletedAt` 为 `null`。现有后端文件接口与前端 `DriveItemResponse.kind` 均使用 `file` / `folder`，本协议不要求后端返回细分类别。

## 创建分享

`POST /api/shares`，需要 `Authorization: Bearer <token>`。

```json
{
  "fileId": "42",
  "expiresInSeconds": 604800
}
```

`expiresInSeconds` 支持 86400（1 天）、604800（7 天）和 2592000（30 天）。仅允许分享当前用户拥有、未删除的普通文件；文件夹和其他用户的文件不可分享。

成功返回 `201 Created` 和 `ShareResponse`。前端入口为手机「文件」页选中单个普通文件后的操作面板「分享」，或 PC 文件列表选中单个文件后的工具栏「分享」。前端输入 1、7 或 30 天并换算为秒；收到成功响应后才展示含有效期和复制按钮的链接弹窗，并在本地分享列表前插入新记录。请求失败时提示错误，不生成链接。

## 查询我的分享

`GET /api/shares`，需要认证。成功返回当前用户的 `ShareResponse[]`，按创建时间倒序；包含已取消或已过期记录，供前端显示历史状态。即使没有分享，也须返回空数组 `[]`，而不是空对象或包装对象。前端手机「我的」→「我的分享」和 PC「我的分享」入口都会调用该接口；手机页面提供全部、分享有效、分享过期和已取消筛选，以及请求失败后的重试入口。底部「共享」是消息/社交占位页，不调用此接口。

## 取消分享

`DELETE /api/shares/{id}`，需要认证。这里使用所有者列表记录中的分享 `id`，不是 `token` 或 `fileId`。只能取消当前用户创建的分享。成功返回 `204 No Content`；重复取消可幂等返回 `204`。前端收到成功响应后将本地记录状态更新为 `CANCELLED`；手机多选取消时按分享逐条调用该接口，部分失败会保留已成功取消的状态。

## 公开查看分享

`GET /api/shares/{token}`，无需登录。成功返回 `200` 和 `ShareAccessResponse`。前端路由 `/share/:token` 调用该接口显示文件名、大小及有效期，访客无需登录；响应中不返回 Token 或文件的原始存储地址。

Token 不存在、已过期、已取消、文件已删除或不可访问时，统一返回 `404 SHARE_NOT_FOUND`，不泄露资源状态。

## 公开下载分享文件

`GET /api/shares/{token}/download`，无需登录。每次下载均须重新验证分享 Token、有效期、取消状态和文件状态。成功返回 `200 OK` 的文件二进制流，`Content-Type: application/octet-stream`，`Content-Disposition` 建议采用现有文件下载接口的 `filename*=UTF-8''...` 格式；前端优先解析该文件名，缺失时使用公开详情中的 `file.name`。不得把 FastDFS 原始地址暴露给浏览器。登录用户下载自己的文件仍使用 `/api/files/{id}/download`，不经过分享接口。

后端安全配置应只对上述两个公开 GET 路径放行匿名访问；创建、列表、取消仍必须校验 Bearer 身份。公开请求由前端独立 Axios 客户端发出，不附带用户 Token。

## 错误码

- `400 INVALID_INPUT`：文件 ID 或有效期参数不合法。
- `401 UNAUTHORIZED`：所有者接口缺少或携带无效 Bearer Token。
- `404 FILE_NOT_FOUND`：创建分享时目标文件不存在、已删除或不属于当前用户。
- `404 SHARE_NOT_FOUND`：公开分享不存在、过期、已取消或对应文件不可用。
- `500 INTERNAL_ERROR`：未预期的服务端错误。

分享状态和有效期以服务端为准。前端本地状态只用于即时更新界面，不得替代接口校验。
