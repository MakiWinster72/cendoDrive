# CendoDrive 本地环境部署

本文适用于在宿主机直接运行 Spring Boot 后端和 Vue 前端，并连接已经安装或单独运行的 MySQL、Redis、FastDFS 和 Qdrant。命令默认从仓库根目录 `cendoDrive/` 执行。

> 本文面向开发和内网验收。公网生产环境还需要 HTTPS、反向代理、密钥管理、访问控制、监控与备份。

## 1. 环境要求

| 组件          | 项目要求或建议版本                    | 默认地址                   | 是否必需               |
| ------------- | ------------------------------------- | -------------------------- | ---------------------- |
| JDK           | 21                                    | —                         | 是                     |
| Maven         | 3.9+                                  | —                         | 是                     |
| Node.js / npm | Node.js 22、npm 10                    | —                         | 是                     |
| Vue           | 由`npm ci` 安装 Vue 3，无需全局安装 | `localhost:5173`         | 是                     |
| MySQL         | 8.x，建议 8.4                         | `localhost:3306`         | 是                     |
| Redis         | 7.x                                   | `localhost:6379`         | 是                     |
| FastDFS       | tracker + 至少一个 storage            | tracker`localhost:22122` | 是                     |
| Qdrant        | 1.15.x                                | `http://localhost:6333`  | 仅启用扣扣 Claw 时需要 |

先检查基础工具：

```sh
java --version
mvn --version
node --version
npm --version
```

`java --version` 和 `mvn --version` 中的 Java 均应为 21。Windows 需要正确设置 `JAVA_HOME`，并把 `%JAVA_HOME%\bin` 加入 `Path`。

## 2. 安装并准备中间件

### 2.1 MySQL

安装并启动 MySQL 8 后，以管理员身份执行：

```sql
CREATE DATABASE cendo CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'cendo'@'localhost' IDENTIFIED BY '请替换为强密码';
GRANT ALL PRIVILEGES ON cendo.* TO 'cendo'@'localhost';
FLUSH PRIVILEGES;
```

如果后端不在数据库本机运行，应将 `localhost` 改为受限的实际来源主机，并在防火墙中只允许该来源。无需手工建表，后端首次启动时由 Flyway 自动迁移。

验证连接：

```sh
mysql -h 127.0.0.1 -P 3306 -u cendo -p cendo
```

### 2.2 Redis

安装并启动 Redis 7。开发环境可使用默认 6379 端口；非本机环境应启用 ACL/密码且不要把端口暴露到公网。

```sh
redis-cli -h 127.0.0.1 -p 6379 ping
```

预期输出 `PONG`。

### 2.3 FastDFS

部署一个 tracker 和至少一个 storage，并确保：

1. tracker 监听 `22122`；storage 监听 `23000`。
2. storage 已向 tracker 注册，状态为 `ACTIVE`。
3. 后端能访问 tracker；同时也能访问 tracker 返回的 storage IP 和端口。
4. tracker 与 storage 的数据目录已持久化，磁盘剩余空间大于待上传文件。

在 tracker 节点验证：

```sh
fdfs_monitor /etc/fdfs/client.conf
```

若使用容器运行 FastDFS，也可只启动仓库提供的依赖服务：

```sh
docker compose up -d tracker storage1 storage2 storage3
docker compose exec tracker fdfs_monitor /etc/fdfs/client.conf
```

跨主机部署和节点地址要求见[《FastDFS 跨主机 Storage 部署设计》](FastDFS跨主机Storage部署设计.md)。

### 2.4 Qdrant（可选）

只有启用扣扣 Claw 文档检索时才需要 Qdrant。安装 Qdrant 1.15.x 并持久化其 storage 目录，或单独启动仓库中的服务：

```sh
docker compose up -d qdrant
curl http://localhost:6333/healthz
```

普通网盘功能和普通 AI 聊天不依赖 Qdrant。

## 3. 配置后端

复制示例配置。本地文件已在 `.gitignore` 中，不要提交密码或 API Key。

```powershell
Copy-Item backend/src/main/resources/application.example.yml backend/src/main/resources/application.yml
```

Linux/macOS/Git Bash 可使用：

```sh
cp backend/src/main/resources/application.example.yml backend/src/main/resources/application.yml
```

编辑 `backend/src/main/resources/application.yml`，至少确认以下内容：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/cendo?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC
    username: cendo
    password: 请替换为数据库密码
  data:
    redis:
      host: localhost
      port: 6379
      password: "" # Redis 启用认证时填写

app:
  cors:
    allowed-origins: http://localhost:5173,http://127.0.0.1:5173

server:
  port: 8080

cendo:
  storage:
    root: ./storage
    backend: fastdfs
  upload:
    root: ./storage/uploads
  ai:
    claw:
      enabled: false
      vector:
        base-url: http://localhost:6333

fdfs:
  tracker-list:
    - localhost:22122
```

也可以不写明文敏感值，使用 `DB_URL`、`DB_USER`、`DB_PASSWORD`、`REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`、`FASTDFS_TRACKER` 等环境变量覆盖。完整字段以 `application.example.yml` 为准。

如需 AI 聊天，配置 `CENDO_AI_CHAT_BASE_URL`、`CENDO_AI_CHAT_MODEL`、`CENDO_AI_CHAT_KEY`；三项必须同时填写。启用扣扣 Claw 时，还需设置 `CENDO_AI_CLAW_ENABLED=true` 及嵌入模型配置，并确保嵌入维度与 Qdrant 集合一致。密钥只能放在后端环境中，不能使用 `VITE_*` 变量。

## 4. 启动后端

```sh
cd backend
mvn spring-boot:run
```

日志出现 `Started CendoDriveApplication` 后，访问：

- API：`http://localhost:8080`
- Swagger UI：`http://localhost:8080/swagger-ui/index.html`

首次启动会自动执行 Flyway 数据库迁移。若启动失败，优先检查 MySQL/Redis 连接、FastDFS 节点地址和 AI 配置是否只填写了一部分。

## 5. 启动前端

另开终端：

```sh
cd frontend
npm ci
npm run dev
```

打开 `http://localhost:5173`。Vite 默认把 `/api` 代理到 `http://localhost:8080`；后端地址不同时，在启动前设置 `VITE_API_PROXY_TARGET`，例如：

```powershell
$env:VITE_API_PROXY_TARGET='http://192.168.1.10:8080'
npm run dev
```

## 6. 部署验收

依次确认：

1. 能打开前端和 Swagger UI。
2. 注册、登录成功，刷新页面后会话正常。
3. 上传文件后能下载并校验内容一致。
4. `fdfs_monitor` 中 storage 保持 `ACTIVE`。
5. 启用 Claw 时，上传受支持文档后能完成索引和检索。

可运行基础检查：

```sh
cd backend && mvn test
cd ../frontend && npm test && npm run build
```

## 7. 常见问题

- `Communications link failure`：MySQL 未启动、地址错误或防火墙未放行。
- Redis 连接失败：检查 6379、认证密码和 bind/ACL 配置。
- FastDFS 报无可用节点：确认 storage 为 `ACTIVE`，并检查后端能否访问 tracker 返回的 storage 地址。
- FastDFS 错误码 28：可用空间低于保留比例；清理磁盘或合理调整 `reserved_storage_space`，不要关闭空间保护。
- 前端接口 404/502：确认后端监听 8080，并检查 `VITE_API_PROXY_TARGET`。
- Claw 返回向量服务不可用：确认 Qdrant 的 6333 可达、API Key（如有）正确、嵌入维度一致。
