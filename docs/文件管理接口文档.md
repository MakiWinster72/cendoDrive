# CendoDrive 文件管理接口文档

## 基本信息

- 开发环境基础地址：`http://localhost:8080`
- 接口前缀：`/api/files`
- 认证：除 Swagger 页面外，所有文件接口都需要 `Authorization: Bearer <token>`
- 时间：`updatedAt` 和 `deletedAt` 为 UTC ISO-8601 字符串
- ID：响应中的 `id` 和 `parentId` 为字符串；请求中的 ID 为整数

后端启动后可查看：

- Swagger UI：`http://localhost:8080/swagger-ui/index.html`
- OpenAPI JSON：`http://localhost:8080/v3/api-docs`

## 数据结构

```json
{
  "id": "42",
  "name": "项目文档",
  "kind": "folder",
  "size": 0,
  "parentId": null,
  "updatedAt": "2026-09-29T06:30:00Z",
  "deletedAt": null
}
```

`kind` 取值为 `folder` 或 `file`；文件夹的 `size` 为 `0`。

## 获取目录内容

`GET /api/files?parentId={folderId}`

- 不传 `parentId` 时查询根目录。
- 仅返回当前登录用户的数据。

成功响应 `200`：

```json
[
  {
    "id": "42",
    "name": "项目文档",
    "kind": "folder",
    "size": 0,
    "parentId": null,
    "updatedAt": "2026-09-29T06:30:00Z",
    "deletedAt": null
  }
]
```

## 新建文件夹

`POST /api/files/folder`

```json
{
  "name": "项目文档",
  "parentId": null
}
```

`parentId` 为 `null` 时在根目录创建。成功返回 `201` 和新建的文件夹对象。

## 重命名

`PUT /api/files/{id}/rename`

```json
{
  "name": "已归档项目"
}
```

成功返回 `200` 和更新后的文件或文件夹对象。

## 移动

`PUT /api/files/{id}/move`

```json
{
  "parentId": 10
}
```

`parentId` 为 `null` 时移到根目录。不允许将文件夹移到自身或它的子孙目录。成功返回 `200` 和更新后的对象。

## 上传

`POST /api/files/upload`，Bearer 认证，`multipart/form-data`：`file`（文件，必填）、`parentId`（整数，可选，省略时为根目录）。最大 100MB，由 Spring multipart 配置限制。成功返回 `201` 和文件对象，`kind=file`、`size` 为实际字节数；文件内容写入 FastDFS，数据库保存 file ID 与 `storage_backend=fastdfs`。名称和父目录校验与新建文件夹一致；上传失败不会返回成功结果。

> 后端须能连接 tracker **和 tracker 返回的 storage 地址:23000**。文件访问始终通过需要登录的 `/api/files` 接口，不公开 FastDFS 原始地址。

## 下载

`GET /api/files/{id}/download`

成功返回 `200`，响应类型为 `application/octet-stream`，`Content-Disposition` 包含 UTF-8 文件名。下载需要数据库记录具有有效 `storage_key`：新上传的文件从 FastDFS 读取；升级前的 `storage_backend=local` 文件仍从 `CENDO_STORAGE_ROOT` 读取。文件夹不能直接下载。FastDFS 下载经过用户权限校验，不要直接向浏览器暴露 storage HTTP URL。

## 分片上传（大文件）

超过 20MB 的大文件由前端自动改用分片上传；小文件仍使用 `POST /api/files/upload`。接口前缀为 `/api/upload`，全部需要 Bearer 认证。服务端把分片暂存在本地磁盘、用 Redis 记录分片状态，并在合并时校验整文件 SHA-256。

流程：`init` → 并发上传 `chunk` →（可选）`status` → `merge`。

### 初始化

`POST /api/upload/init`

```json
{
  "name": "movie.mp4",
  "parentId": 10,
  "totalSize": 52428800,
  "fileHash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
}
```

- `fileHash` 为整文件 SHA-256，必须是 64 位十六进制。
- 名称、父目录与配额校验与普通上传一致；不满足时直接返回错误，不会创建上传任务。
- `uploadId` 由 `ownerId|parentId|name|totalSize|fileHash` 派生，重复调用会命中同一会话，因此刷新或重试后无需前端保存 `uploadId`。

成功响应 `200`：

```json
{
  "uploadId": "5c1f0a7b2d9e4f6380a1b2c3d4e5f60718293a4b5c6d7e8f90a1b2c3d4e5f607",
  "chunkSize": 5242880,
  "totalChunks": 10,
  "uploadedIndexes": [0, 1],
  "status": "UPLOADING"
}
```

- `status` 为 `UPLOADING` 时按 `uploadedIndexes` 跳过已上传分片，实现断点续传。
- `status` 为 `COMPLETED` 时表示同一文件此前已合并成功，直接调用 `merge` 取回文件对象即可。

### 上传分片

`POST /api/upload/chunk`，`multipart/form-data`：

| 字段        | 说明                                    |
| ----------- | --------------------------------------- |
| `file`      | 分片二进制内容                          |
| `uploadId`  | init 返回的会话 ID                      |
| `index`     | 分片下标，从 0 开始                     |
| `chunkHash` | 该分片的 SHA-256（64 位十六进制）       |

- 除最后一片外，分片大小必须等于 `chunkSize`；最后一片是剩余字节数。
- 分片先写临时文件并校验 `chunkHash`，通过后才原子落盘并更新 Redis 位图；同一分片重复上传是幂等的。
- 会话必须属于当前登录用户，否则返回 `UPLOAD_NOT_FOUND`。

成功响应 `200`：

```json
{
  "uploadId": "5c1f0a7b2d9e4f6380a1b2c3d4e5f60718293a4b5c6d7e8f90a1b2c3d4e5f607",
  "receivedIndexes": [0, 1, 2],
  "received": 3,
  "totalChunks": 10
}
```

### 查询状态

`GET /api/upload/{uploadId}/status`

```json
{
  "uploadId": "5c1f0a7b2d9e4f6380a1b2c3d4e5f60718293a4b5c6d7e8f90a1b2c3d4e5f607",
  "status": "UPLOADING",
  "chunkSize": 5242880,
  "totalChunks": 10,
  "uploadedIndexes": [0, 1, 2],
  "missingIndexes": [3, 4, 5, 6, 7, 8, 9],
  "received": 3,
  "totalSize": 52428800
}
```

### 合并

`POST /api/upload/merge`

```json
{ "uploadId": "5c1f0a7b2d9e4f6380a1b2c3d4e5f60718293a4b5c6d7e8f90a1b2c3d4e5f607" }
```

- 校验分片齐全后按序拼接，边拼接边计算整文件 SHA-256，与 init 声明的 `fileHash` 比对。
- 校验通过后写入 FastDFS 并落库，返回 `201` 和文件对象（结构同普通上传）。
- 合并前会重新校验同名冲突与配额。
- 并发或重复的 `merge` 由分布式锁保护：同会话已有合并在进行时返回 `UPLOAD_IN_PROGRESS`；已合并成功的会话再次调用会直接返回同一文件对象。
- 合并成功后临时分片与 Redis 会话状态会被清理；被放弃的会话在过期（默认 24 小时）后由清理任务回收（默认开启，见 `cendo.upload.cleanup-enabled`）。
- 若合并时发现某个分片文件已丢失，服务端会清除该分片的完成标记并返回 `CHUNK_INCOMPLETE`，客户端重传该分片即可，无需整文件重传。

## 回收站

回收站使用软删除。文件移入回收站后，数据库记录仍然存在，`deletedAt` 保存删除时间；正常目录列表只返回 `deletedAt` 为 `null` 的项目。

### 获取回收站列表

`GET /api/files/trash`

- 返回当前登录用户的回收站项目。
- 结果按删除时间倒序排列。
- 如果已删除项目的父目录也在回收站中，只返回顶层父目录，避免子项重复显示。

成功响应 `200`：

```json
[
  {
    "id": "42",
    "name": "已删除项目",
    "kind": "folder",
    "size": 0,
    "parentId": null,
    "updatedAt": "2026-09-29T06:30:00Z",
    "deletedAt": "2026-09-30T01:20:00Z"
  }
]
```

### 移入回收站

`POST /api/files/trash`

请求体：

```json
{
  "ids": [42, 43]
}
```

- 支持单项和批量操作。
- 所有项目必须属于当前登录用户。
- 操作在同一个数据库事务中执行。
- 已经位于回收站中的项目不能重复删除。

成功返回 `200` 和更新后的文件对象数组，其中 `deletedAt` 已设置。

### 恢复

`POST /api/files/trash/restore`

请求体：

```json
{
  "ids": [42, 43]
}
```

- 支持单项和批量恢复。
- 文件恢复到原目录。
- 如果原父目录仍在回收站中，恢复失败并返回 `PARENT_IN_TRASH`。
- 如果原目录中存在同名项目，恢复失败并返回 `NAME_CONFLICT`。

成功返回 `200` 和恢复后的文件对象数组，其中 `deletedAt` 为 `null`。

### 永久删除

`POST /api/files/trash/delete`

请求体：

```json
{
  "ids": [42, 43]
}
```

- 只允许永久删除已经位于回收站中的项目。
- 删除文件夹记录时，数据库外键会级联删除其子记录。
- 当前接口删除数据库记录；实际存储文件的清理需要在上传和存储功能接入后补充。

成功返回 `204 No Content`。

### 清空回收站

`DELETE /api/files/trash`

- 永久删除当前登录用户回收站中的全部项目。
- 不影响其他用户的数据。

成功返回 `204 No Content`。

## 批量操作规则

- `ids` 不能为空，空数组返回 `INVALID_SELECTION`。
- 重复 ID 会自动去重。
- 任一 ID 不存在或不属于当前用户时，整个操作失败。
- 前端只在接口成功后更新状态和显示成功提示。

## 错误响应

```json
{
  "code": "NAME_CONFLICT",
  "message": "An item with the same name already exists",
  "fields": {}
}
```

| HTTP | code                       | 含义                                 |
| ---- | -------------------------- | ------------------------------------ |
| 400  | `INVALID_INPUT`            | 请求字段校验失败                     |
| 400  | `INVALID_JSON`             | JSON 无法解析                        |
| 400  | `INVALID_NAME`             | 名称为空、`.`、`..` 或包含路径分隔符 |
| 400  | `NOT_A_FOLDER`             | 指定的父目录或目标不是文件夹         |
| 400  | `INVALID_MOVE`             | 移动到自身或子孙目录                 |
| 400  | `FOLDER_NOT_DOWNLOADABLE`  | 尝试下载文件夹                       |
| 400  | `INVALID_SELECTION`        | 批量操作未选择任何项目               |
| 401  | `UNAUTHORIZED`             | 未携带 Token 或 Token 无效           |
| 404  | `FILE_NOT_FOUND`           | 文件或文件夹不存在，或不属于当前用户 |
| 404  | `CONTENT_NOT_FOUND`        | 文件内容不存在                       |
| 409  | `NAME_CONFLICT`            | 目标目录已存在同名项                 |
| 409  | `ALREADY_IN_TRASH`         | 项目已经位于回收站                   |
| 409  | `NOT_IN_TRASH`             | 对正常项目执行了仅限回收站的操作     |
| 409  | `PARENT_IN_TRASH`          | 恢复项目时，其父目录仍在回收站       |
| 409  | `CHUNK_INCOMPLETE`         | 合并时仍有分片未上传，或分片文件已丢失 |
| 409  | `UPLOAD_IN_PROGRESS`       | 同一上传会话正在合并中，或已完成合并   |
| 413  | `MAX_UPLOAD_SIZE_EXCEEDED` | 上传超过 multipart 限制              |
| 400  | `INVALID_CHUNK`            | 分片下标越界或分片大小不符           |
| 400  | `CHECKSUM_MISMATCH`        | 分片或合并后的文件校验和不一致       |
| 404  | `UPLOAD_NOT_FOUND`         | 上传会话不存在、已过期或不属于当前用户 |
| 503  | `STORAGE_UNAVAILABLE`      | 存储服务暂不可用                     |

## 名称规则

- 名称去除首尾空格后不能为空。
- 最长 255 个字符。
- 不能是 `.` 或 `..`。
- 不能包含 `/` 或 `\`。
- 同一目录下的名称不能重复，忽略大小写。

## 当前实现边界

- 单文件上限 100MB，由 Spring multipart 配置限制；大文件通过 `/api/upload/*` 分片上传，前端对超过 20MB 的文件自动切换。
- 临时分片存放在后端本地磁盘（`cendo.upload.chunk-root`），当前部署为单实例；多实例部署需替换为共享存储实现。
- 分片会话默认 24 小时过期；孤儿分片清理任务默认开启（`cendo.upload.cleanup-enabled`），只回收 Redis 会话已过期且超过宽限期未改动的目录。
- 分享页仍使用 Mock 文件下载，尚未接入真实分享接口。
- 永久删除会同时清理 FastDFS 内容；升级前的 `storage_backend=local` 物理文件仍不清理。
