# 文件管理接口与开发记录

前端接入见 [文件管理前端对接指南](文件管理前端对接指南.md)；团队分工和阶段检查见 [文件模块协作与交付清单](文件模块协作与交付清单.md)。当前代码待用户分阶段检查与提交，未部署到共享环境。

## 范围与阶段

本模块管理文件元数据和逻辑目录，不执行 FastDFS 上传、下载、删除，也不提供客户端任意登记存储地址的接口。

| 阶段 | 交付 |
| --- | --- |
| 1 数据基础 | V2 文件表、FileEntry、Repository、名称规则、用户行锁 |
| 2 查询与创建 | 分页文件列表、新建文件夹、用户隔离 |
| 3 目录修改 | 重命名、移动、防目录成环、PUT 跨域预检 |
| 4 文件登记 | 内部登记服务、容量事务、上传任务幂等 |
| 5 验证与联调 | 单元测试、MVC 测试、独立 MySQL 集成测试、本接口文档 |

## 数据规则与基础用户隔离

本次任务只保留单用户私有空间所需的基础隔离：从现有认证上下文取得 userId，列表和条目操作按该 userId 定位数据，不接受客户端指定 userId。角色、共享授权、管理员权限、跨用户协作等额外权限模块不在本次范围内。

- `file_entries` 统一保存 FILE/FOLDER；`parent_id=0` 表示当前用户的虚拟根目录，没有真实根目录记录。
- 所有 HTTP 接口复用项目已有 Bearer Token 认证；用户 ID 仅来自当前认证用户，不接受客户端指定归属。
- 非根目录和目标条目按 ID + user_id 查询；不存在和其他用户条目都返回 404。
- 父目录必须是自己的文件夹。根目录不能重命名或移动。
- 名称先拒绝任意位置的控制字符和孤立代理字符，再 strip、NFC 规范化；最长 255 个 Java UTF-16 单元；拒绝空名称、`.`、`..`、`/` 和 `\`。
- name_key 使用 Locale.ROOT 小写再 NFC 规范化，数据库 utf8mb4_bin 判重。同目录文件和文件夹共享名称空间。
- 同用户所有元数据写操作先锁 users 行，再读取/修改文件条目。事务内不调用外部存储服务。未来删除/恢复模块必须遵循同样的锁顺序。
- 文件夹大小固定为 0。重命名和移动不修改 storage_key，不改变容量。
- `users.storage_used` 表示已登记文件字节数之和；同一物理对象的不同登记按逻辑文件分别计量。
- 时间使用 UTC；输出 ID 为十进制字符串，大小为字节数。
- 当前未实现回收站。接入回收站前必须调整有效条目的同名唯一规则，并定义容量释放和幂等记录保留策略。

V2 要求 MySQL 8.0.16+ 以执行 CHECK 约束。parent_id 因虚拟根而不设外键，由服务层保证合法性；其他模块不能直接修改目录关系。

## HTTP API

所有请求带 `Authorization: Bearer <token>`。本地前端可继续使用 Vite `/api` 代理。

### GET /api/files

参数：parentId 默认 0；page 默认 0；size 默认 50，范围 1–100。拒绝负数和超出 JPA 可表示 offset 的分页。

仅列出直接子项，文件夹优先，再按 ID 升序。当前不提供搜索或自定义排序。

```json
{
  "parentId": "0",
  "items": [{
    "id": "101",
    "parentId": "0",
    "name": "工作资料",
    "entryType": "FOLDER",
    "sizeBytes": 0,
    "contentType": null,
    "createdAt": "2026-09-29T03:00:00Z",
    "updatedAt": "2026-09-29T03:00:00Z"
  }],
  "page": 0,
  "size": 50,
  "totalElements": 1
}
```

### POST /api/files/folder

```json
{"parentId":"0","name":"工作资料"}
```

parentId 必填；成功返回 201 和单个条目 DTO。

### PUT /api/files/{id}/rename

```json
{"name":"项目资料"}
```

成功返回 200 和更新后的条目。重命名为自身当前名称正常成功，仅修改大小写允许。

### PUT /api/files/{id}/move

```json
{"targetParentId":"123"}
```

targetParentId 必填，0 表示移回根目录。成功返回 200 和更新后的条目；原目录移动为幂等空操作。

文件夹不能移入自身或任意后代目录。通过目标祖先链检查，已访问 ID 集合防止异常数据导致无限循环。

响应不包含 storage_key、ingest_key、登记指纹或实体内部字段。

### 错误

统一结构：`{"code":"NAME_CONFLICT","message":"...","fields":{}}`。

| HTTP | code | 含义 |
| --- | --- | --- |
| 400 | INVALID_INPUT / INVALID_JSON | 缺失字段、参数类型、分页或 JSON 错误 |
| 400 | INVALID_NAME | 名称非法 |
| 400 | NOT_A_FOLDER | 自有目标条目不是文件夹 |
| 400 | INVALID_MOVE | 移动造成循环，或祖先链已有循环 |
| 400 | INVALID_METADATA | 内部登记参数非法 |
| 401 | UNAUTHORIZED | 未登录、凭证失效或账号失效 |
| 404 | FILE_NOT_FOUND | 不存在或无权访问 |
| 409 | NAME_CONFLICT | 同目录名称冲突 |
| 409 | STORAGE_QUOTA_EXCEEDED | 容量不足 |
| 409 | IDEMPOTENCY_CONFLICT | 上传任务参数不一致 |

未知数据库约束异常返回 500 INTERNAL_ERROR，不暴露 SQL、存储标识或数据库结构。存储故障、锁超时等基础设施错误不等同于业务冲突。

## 上传模块内部对接

注入 `FileMetadataService`，调用：

```java
FileEntryResponse result = metadata.registerStoredFile(authenticatedUserId,
    new RegisterStoredFileCommand(
        parentId, originalName, actualSizeBytes,
        "FASTDFS", serverReturnedStorageKey,
        detectedContentType, contentHash, uploadTaskId));
```

- 用户身份必须来自认证上下文/可信上传任务。大小、存储标识来自服务端上传结果，不能信任客户端声明。
- ingestKey 必填，1–64 位 ASCII 字母、数字、下划线或连字符；同一次上传重试必须稳定。
- storageProvider 必填，最长 32；storageKey 必填，最长 512；contentType 可空，最长 255；contentHash 可空，最长 128，建议 `sha256:...`。
- 本服务锁用户行，检查已有任务，然后校验目录、名称和容量，原子写入文件与 storage_used。
- 存储初次登记的 SHA-256 参数指纹。同任务同参数重试返回现有条目，即使条目后来已重命名/移动；参数不同返回 IDEMPOTENCY_CONFLICT。返回条目内容为当前状态。
- 上传同事不得再次增加 storage_used。目录操作不影响容量。
- 外部存储上传发生在数据库事务外；不要从持有长事务/旧快照的调用方执行登记。
- 落库确定失败时，上传模块清理本次产生的独立存储对象；结果未知时先重试同一登记命令确认，禁止直接删除可能已经登记的文件。共享存储对象需另行设计引用计数。
- 同一成功任务后续若重新上传产生不同 storageKey，不能沿用原 ingestKey；上传模块应复用首次上传结果。

## 开发与验证

必须使用 JDK 21。Windows PowerShell 示例（JAVA_HOME 根据本机路径调整）：

```powershell
$env:JAVA_HOME = 'C:\Users\87291\.jdks\microsoft-21'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
java -version
mvn test
```

默认运行单元/MVC 测试，不连接数据库。数据库集成测试必须配置专用测试库，不使用 application.yml 的共享数据库默认地址：

```powershell
$env:RUN_FILE_INTEGRATION_TESTS = 'true'
$env:FILE_TEST_DB_URL = 'jdbc:mysql://127.0.0.1:3306/cendo_file_test?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC'
$env:FILE_TEST_DB_USER = '<专用测试库账号>'
# FILE_TEST_DB_PASSWORD 通过本机环境注入，不提交到仓库。
mvn '-Dtest=FileIntegrationTest' test
```

测试库会执行 Flyway V1/V2。测试创建随机命名用户，结束后仅清理对应条目和用户；测试中断时可能留下测试数据。测试服务层无需 Redis 或 FastDFS；真实 Bearer 认证联调仍需要 Redis。

集成测试覆盖：目录生命周期、跨用户隔离、数据库根目录判重、分页排序、外层事务回滚、并发同名、并发互移、并发容量竞争、并发幂等重试。
