# CendoDrive 认证与用户接口文档

本地接口地址：`http://localhost:8080`。OpenAPI 定义见 `/v3/api-docs`，调试页面见 `/swagger-ui/index.html`。

## 通用约定

- `createdAt` 是 UTC 时间，返回带 `Z` 的 ISO-8601 字符串，例如 `2026-09-28T08:24:29Z`。数据库 `DATETIME(6)` 按 UTC 写入。
- 用户 ID 以十进制字符串返回，不要在前端转成 JavaScript `Number`。
- 需认证的接口使用 `Authorization: Bearer <token>`。Token 有效期为 86400 秒；退出登录只撤销当前 Token。
- 成功响应沿用 HTTP 状态码和业务 DTO，不额外包装：注册返回 `201` 与 `UserResponse`，登录及当前用户返回 `200` 与对应 DTO，退出返回无响应体的 `204`。前端不得假设存在顶层 `data` 字段。
- 已处理的错误响应采用 `{ "code": string, "message": string, "fields": Record<string, string> }`；校验失败时 `fields` 按字段列出错误，其余情况是空对象。前端按状态码、`code` 和字段名判断，不依赖英文 `message` 或校验器文案。未经统一处理的框架错误暂不在此约定内。
- 状态码约定：`400` 为输入或 JSON 错误，`401` 为缺少/无效认证或登录失败，`409` 仅应表示已确认的用户名唯一约束冲突，`429` 为登录限流；未预期的服务端错误不应伪装为用户名冲突。无法确定为用户名唯一约束冲突的数据库完整性错误返回 `500 INTERNAL_ERROR`，不向客户端暴露数据库细节。

## 用户摘要 `UserResponse`

| 字段           | 类型   | 说明                                      |
| -------------- | ------ | ----------------------------------------- |
| `id`           | string | 十进制用户 ID                             |
| `username`     | string | 小写用户名                                |
| `nickname`     | string | 昵称，默认与用户名相同                    |
| `createdAt`    | string | UTC 注册时间，带 `Z`                      |
| `vipLevel`     | string | 当前为 `NORMAL`，会员功能尚未实现         |
| `storageUsed`  | number | 已用字节数，当前为 `0`                    |
| `storageLimit` | number | 总容量，当前为 `1073741824` 字节（1 GiB） |

## 1. 注册

`POST /api/auth/register`，无需认证。

请求体：

```json
{
  "username": "maki_01",
  "password": "example-password-123",
  "nickname": "Maki"
}
```

- `username`：必填，3–64 个字符，只允许英文字母、数字和下划线；写入前转小写。数据库中不可重复。
- `password`：必填，8–128 个字符；服务端使用 BCrypt 保存哈希。
- `nickname`：可选，最多 64 个字符；省略或仅空白字符时默认使用用户名。
- 注册接口不接收角色、会员等级、容量和启用状态；请求中即使带上这些字段，也不会写入用户记录。

成功：`201 Created`，响应体为 `UserResponse`，例如：

```json
{
  "id": "1",
  "username": "maki_01",
  "nickname": "Maki",
  "createdAt": "2026-09-28T08:24:29.704469Z",
  "vipLevel": "NORMAL",
  "storageUsed": 0,
  "storageLimit": 1073741824
}
```

输入不合法返回 `400 INVALID_INPUT`；确认用户名唯一键冲突时返回 `409 CONFLICT`。其他数据库完整性错误返回 `500 INTERNAL_ERROR`。

## 2. 登录

`POST /api/auth/login`，无需认证。

请求体：

```json
{ "username": "maki_01", "password": "example-password-123" }
```

两个字段均必填、不得为空白；查询用户名时去首尾空白并转小写。成功：`200 OK`：

```json
{
  "token": "仅在登录成功时返回的随机凭证",
  "expiresInSeconds": 86400,
  "user": {
    "id": "1",
    "username": "maki_01",
    "nickname": "Maki",
    "createdAt": "2026-09-28T08:24:29.704469Z",
    "vipLevel": "NORMAL",
    "storageUsed": 0,
    "storageLimit": 1073741824
  }
}
```

字段为空或缺失返回 `400 INVALID_INPUT`。账号不存在、密码错误、账号禁用统一返回 `401 UNAUTHORIZED`，响应信息为 `Invalid credentials`。

同一用户名 15 分钟内累计失败 5 次，第 5 次起返回 `429 RATE_LIMITED`，响应头 `Retry-After: 900`。成功登录会清除失败计数。该限制按用户名计算，暂未按来源 IP 限制；`900` 为固定提示值，并非实时剩余秒数。

## 3. 获取当前用户

`GET /api/user/me`，需 `Authorization: Bearer <token>`，无请求体。

成功返回 `200` 和 `UserResponse`。未携带 Token、Token 无效或已过期、已退出登录、用户被禁用时返回 `401 UNAUTHORIZED`。

## 4. 退出登录

`POST /api/auth/logout`，需 `Authorization: Bearer <token>`，无请求体。

成功返回 `204`，无响应体。仅撤销本次请求使用的 Token，其他设备不受影响。退出后再次使用该 Token 访问 `/api/user/me` 返回 `401`；缺少或无效 Token 也返回 `401`。

## 错误响应

参数校验失败示例（`400`）：

```json
{
  "code": "INVALID_INPUT",
  "message": "Invalid input",
  "fields": { "username": "must match ..." }
}
```

`fields` 中的提示文本来自校验器，客户端应使用 `code` 和字段名判断，不依赖提示文本原样不变。无字段错误时 `fields` 为 `{}`。其他常见错误码：`INVALID_JSON`（JSON 无法解析，400）、`UNAUTHORIZED`（401）、`CONFLICT`（409）、`RATE_LIMITED`（429）。

## 本地联调

以下密码仅用于本机测试，不要把真实密码或 Token 写进仓库、文档或日志。

```sh
curl -i -X POST http://localhost:8080/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"maki_01","password":"example-password-123","nickname":"Maki"}'

curl -i -X POST http://localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"maki_01","password":"example-password-123"}'

# 将登录响应的 token 放在当前终端变量中；避免把真实 token 提交到 Git。
TOKEN='将登录响应中的token粘贴到这里'
curl -i http://localhost:8080/api/user/me -H "Authorization: Bearer $TOKEN"
curl -i -X POST http://localhost:8080/api/auth/logout -H "Authorization: Bearer $TOKEN"
curl -i http://localhost:8080/api/user/me -H "Authorization: Bearer $TOKEN"  # 预期 401
```
