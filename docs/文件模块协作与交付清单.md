## 上传协作时序

1. 上传模块取得当前用户身份，提前检查目录与容量，完成 FastDFS 存储。
2. 从服务端结果取得实际大小与 storageKey，以稳定上传任务 ID 调用登记服务。
3. 登记服务在短事务内锁定用户行，验证目录、同名、容量，写元数据并增加已用容量。
4. 同一任务同参数重试返回原条目；参数不同返回 IDEMPOTENCY_CONFLICT。不能再次增加容量。
5. 确定失败才清理本次产生的独立存储对象；结果未知先用同一任务和参数重试确认。

FastDFS 调用不放在文件元数据事务内。其他模块不得绕过服务直接改 parent_id、user_id 或 storage_used；未来元数据写服务必须使用一致的用户行锁顺序。
