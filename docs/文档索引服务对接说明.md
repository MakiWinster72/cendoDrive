## 3. 对契约「待确认」项的正式答复

### 3.1 FastDFS 读取失败由文档索引服务内部重试（确认：是）

- 事件接口**只负责接收**：收到合法请求立即返回 `202`，随后异步入队处理，不同步等待解析与写入。
- 返回 `2xx` 之后的 FastDFS 读取失败、解析失败等，均由文档索引服务内部按第 6 节策略重试，不回退给 Lucky。
- 处理按 `eventId` 幂等。

### 3.2 读取文件前检查 revision（确认：是，且写入时二次校验）

- **前置检查（成本保护）**：`UPSERT` 读取文件前，先比对 `(ownerId, fileId)` 已处理的最大 `revision`；若 `incoming <= max`，直接忽略并返回成功，不读取文件。
- **写入时原子校验（正确性，必须）**：写入 Milvus 前再做一次比较并原子提交，防止旧事件晚到覆盖新状态（对应验收 AI-14）。

```text
状态字段：(ownerId, fileId) → applied_revision（已生效）, pending_revision（已受理最大值）

接收事件：
  revision <  applied_revision → 200 ignored
  revision == applied_revision → 200 ignored（重复）
  revision >  applied_revision → pending_revision = revision，入队

写入前 CAS：
  if 本次 revision < applied_revision → 放弃写入
  else → 写入向量，applied_revision = 本次 revision
```

## 4. 接口响应约定

| 情况 | HTTP | 响应体 | Lucky 侧动作 |
| --- | --- | --- | --- |
| 首次受理 | `202` | `{"eventId":"...","accepted":true}` | 标记投递成功 |
| 重复 / 旧事件 | `200` | `{"eventId":"...","accepted":true,"ignored":true}` | 标记投递成功 |
| 请求内容错误 | `400` | `{"code":"INVALID_INDEX_EVENT","message":"...","retryable":false}` | 永久失败 |
| 服务暂时不可用 | `503` | `{"code":"INDEX_SERVICE_UNAVAILABLE","message":"...","retryable":true}` | 稍后重试 |

- 业务错误一律使用 `400`；**不使用** `404`、`409`、`422` 等其它 4xx，否则会被 Lucky 判定为可重试并反复投递直至 `DEAD`。
- "不支持的类型"不视为错误：返回 `202`，状态记为 `UNSUPPORTED`。

## 5. 幂等与乱序

- **幂等键**：`eventId`，格式 `file-{fileId}-{revision}-{operation}`。重复事件不重复生成或删除数据，返回 `200 ignored`。
- **乱序规则**（按 `ownerId + fileId` 比对已处理最大 `revision`）：

| 收到版本 | 处理规则 |
| --- | --- |
| 小于已处理版本 | 忽略业务处理，返回成功 |
| 等于已处理版本 | 按重复事件处理，返回成功 |
| 大于已处理版本 | 正常执行事件 |

## 6. 内部重试参数

| 参数 | 取值 |
| --- | --- |
| 异步化 | 接口线程仅入队，立即返回 `202` |
| 最大内部尝试次数 | 12 次 |
| 退避序列 | 30s → 1m → 5m → 15m → 30m → 1h → 2h → 6h → 12h → 12h → 12h |
| 单次读取超时 | 连接 3s / 读取 30s |
| 可重试错误 | Tracker / Storage 不可达、超时、连接重置 |
| 不重试（直接 `FAILED`） | 文档格式损坏、解析超时、超出大小或页数上限 |
| 文件不存在（ENOENT） | 有界重试 3 次后置 `FAILED(FILE_MISSING)` |
| 超过最大尝试次数 | 置 `FAILED`，保留错误信息，不丢弃记录 |

## 7. 解析与分块参数

| 项 | 取值 | 备注 |
| --- | --- | --- |
| 支持格式 | PDF、DOCX、TXT、Markdown（`.md` / `.markdown`） | 其余记 `UNSUPPORTED`，返回 `202` |
| 单文件大小上限 | 50 MB | 可配置；超限记 `UNSUPPORTED`（原因 `TOO_LARGE`） |
| PDF 页数上限 | 1000 页 | 可配置 |
| 单文件解析超时 | 120 s | 可配置 |
| 文本编码 | UTF-8 → BOM 探测 → GBK 兜底 | 中文文档防乱码 |
| 分块大小 | 800 字符 | 文档索引服务自主，可随 Maki 的片段需求调整 |
| 分块重叠 | 100 字符 | 同上 |
| 分块边界 | 优先段落、句子边界 | 同上 |
| 空文本 / 扫描件（无文字层） | 记 `EMPTY_TEXT`，不生成向量 | 不影响文件上传结果 |

> 依据契约第 2 节："本期不包含 Chunk 参数和模型参数"。以上分块参数属文档索引服务内部实现；若 Maki 对搜索结果的片段（`snippets`）有长度或高亮要求，双方另行对齐后调整。

## 8. Embedding 与 Milvus（依赖 Maki 提供）

**需要 Maki 提供：**

- Embedding 模型名称与向量维度；
- Milvus 地址与集合 schema（字段名、类型、主键）；
- 相似度度量方式（如 COSINE、L2）。

**文档索引服务拟采用的写入与停用语义（待 Maki 确认）：**

- 写入键：`ownerId + fileId + chunk`；`ownerId`、`fileId` 以字符串存储，避免大整数精度问题；
- 停用表达：使用 `active` 字段区分。`DEACTIVATE` 置 `false` 并保留向量，`DELETE` 物理删除该 `ownerId + fileId` 的全部向量。请 Maki 确认检索过滤条件与此一致。

## 9. 索引状态模型

| 状态 | 含义 |
| --- | --- |
| `RECEIVED` | 事件已受理 |
| `PARSING` / `CHUNKED` / `EMBEDDED` | 处理中间态 |
| `INDEXED` | 已可搜索 |
| `DEACTIVATED` | 已退出搜索，保留向量 |
| `DELETED` | 向量已清理 |
| `UNSUPPORTED` | 类型不支持 |
| `EMPTY_TEXT` | 空文本或扫描件 |
| `FAILED` / `FILE_MISSING` | 处理失败 / 文件缺失，保留错误信息 |
| `IGNORED` | 写入前发现已被更高 `revision` 取代，放弃写入 |

> 状态存储于文档索引服务自身存储。状态回传或查询通道待与 Lucky、Landen 对齐（契约本期无回调接口）。

## 11. 需要队友提供或确认（Open Items）

**Lucky**

1. FastDFS tracker 地址、storage:23000 可达性与读取凭据或网络要求。

3. 搜索结果片段的取用规则：使用哪些 chunk、长度上限、是否高亮。

## 12. 与验收用例的对应

| 编号 | 场景 | 文档索引服务侧动作 |
| --- | --- | --- |
| AI-01 / AI-02 | 普通上传、分片合并成功 | 收到一次有效 `UPSERT` 并建立索引 |
| AI-03 | 重复投递相同 `eventId` | 不重复生成，返回 `2xx` |
| AI-04 / AI-14 | 旧版本事件晚到 | 按 `revision` 忽略，不覆盖当前状态 |
| AI-05 | 文件移入回收站 | `DEACTIVATE`，文件退出搜索 |
| AI-06 | 文件从回收站恢复 | 更高版本 `UPSERT`，文件重新可搜索 |

| AI-15 | FastDFS 原文件已不存在 | `DELETE` 仍按幂等成功处理 |
