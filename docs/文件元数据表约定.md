# 文件元数据表约定（阶段 1）

适用分支：Lucky-file-management。本文只描述阶段 1 的表结构和共享约定。列表、新建、重命名、移动及文件登记服务也已包含在提交 `764ad1e`，各阶段的用户验收状态仍待确认。

## 结构

Flyway `V2__create_file_entries.sql` 创建 `file_entries`，要求 MySQL 8.0.16+。文件和文件夹共用一张表，以 `entry_type=FILE/FOLDER` 区分。

| 字段 | 用途 |
| --- | --- |
| id | 自增条目 ID，API 输出为十进制字符串 |
| user_id | 所属用户，外键指向 users.id |
| parent_id | 父目录 ID，0 为虚拟根目录 |
| name / name_key | 展示名称 / 同目录判重键 |
| entry_type | FILE 或 FOLDER |
| size_bytes | 字节数，文件夹为 0 |
| storage_provider / storage_key | 文件存储位置，文件夹为空 |
| content_type / content_hash | 可选文件类型、摘要 |
| ingest_key / registration_fingerprint | 文件登记幂等键及原始参数指纹，文件夹为空 |
| created_at / updated_at | UTC 时间 |

唯一键 `(user_id, parent_id, name_key)` 限制同一用户同一目录的文件与文件夹重名；`(user_id, ingest_key)` 约束同一上传任务重复登记。索引 `(user_id, parent_id, entry_type, id)` 支持目录列表。`parent_id=0` 因虚拟根目录不设父目录外键，未来写服务必须验证目录存在及类型。

## 名称规则

`FileNamePolicy` 先拒绝输入中任意位置的控制字符与孤立代理字符，再去首尾空白并规范化为 NFC。名称不能为空、`.`、`..`，不能含 `/`、`\`，规范化展示名及小写判重键都不超过 255 个 Java UTF-16 单元。判重键按 `Locale.ROOT` 转小写，再做 NFC 规范化；数据库使用 `utf8mb4_bin` 保存判重键。

同目录名称大小写不敏感；不同用户或不同目录可以重名。用户 ID 来自现有登录用户，私有目录的基础用户隔离保留。本阶段不增加角色、共享授权或其他权限模块。

## 协作约定

- 合并前确认 Flyway V2 未被他人占用；迁移一旦在共享环境执行，后续只能新增迁移，不能修改 V2。
- `storage_key` 仅供后端内部使用，不直接返回浏览器。文件夹没有 FastDFS 对象。
- 文件容量由后续文件登记服务更新；其他模块不要直接写 `storage_used`。
- 后续所有目录/容量写操作统一先锁定 users 行，保证同用户写操作的并发顺序；锁内不得执行 FastDFS 调用。
- 回收站尚未设计，接入时需重新审视同名唯一约束和永久删除后的幂等键保留规则。
