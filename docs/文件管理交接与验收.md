# 文件管理交接与验收

更新日期：2026-09-30。代码分支：`Lucky-file-management`。本文给前端、上传模块和验收同事使用。请先确认运行的后端代码确实包含此分支；同名 `/api/files` 在其他分支上可能采用不同协议。

## 1. 交付范围和状态

本分支提供文件/文件夹统一元数据表、分页文件列表、新建文件夹、重命名、移动，以及供后端上传模块调用的文件信息登记服务。现有 Bearer Token 认证继续使用；文件查询保留当前用户私有空间所需的基础隔离。角色授权、分享权限等额外权限模块不在本次任务范围内。

| 能力 | 当前状态 | 验证方式 |
| --- | --- | --- |
| 表结构与迁移 | 已编码 | 专用 MySQL 空库启动，检查 Flyway V2 |
| 列表、新建、重命名、移动 | 已编码 | 后端测试和第 4 节 HTTP 手工流程 |
| 文件信息落库和容量更新 | 已编码为内部服务 | `FileMetadataServiceTest`、`FileIntegrationTest` |
| 前端页面接入 | 待前端同事完成 | 第 5 节浏览器验收 |
| FastDFS 真实上传/下载 | 待上传/下载模块完成 | 联调后单独验收 |
| 共享环境部署及合并 | 未验收 | 以团队 PR/MR 和环境记录为准 |

## 2. 对接契约

后端默认 `http://localhost:8080`，接口前缀 `/api`。全部文件接口要求 `Authorization: Bearer <token>`。前端现有 `frontend/src/api/http.ts` 已设置 `baseURL='/api'` 并注入 Token，因此调用路径写 `/files`，不能重复写 `/api/files`。

| 操作 | 请求 | 成功返回 |
| --- | --- | --- |
| 列表 | `GET /api/files?parentId=0&page=0&size=50` | 200，`FileListResponse` |
| 新建文件夹 | `POST /api/files/folder`，`{"parentId":"0","name":"资料"}` | 201，`FileEntryResponse` |
| 重命名 | `PUT /api/files/{id}/rename`，`{"name":"新名称"}` | 200，`FileEntryResponse` |
| 移动 | `PUT /api/files/{id}/move`，`{"targetParentId":"0"}` | 200，`FileEntryResponse` |

根目录为字符串 `"0"`，不能传 `null`。请求中的 ID 可用十进制字符串；响应中的 ID 都是字符串，前端不得转成 JavaScript Number。分页从 0 开始，size 范围 1–100。列表只包含当前目录的直接子项，文件夹优先、ID 升序。

列表响应示例：

```json
{
  "parentId": "0",
  "items": [{
    "id": "101",
    "parentId": "0",
    "name": "资料",
    "entryType": "FOLDER",
    "sizeBytes": 0,
    "contentType": null,
    "createdAt": "2026-09-30T02:00:00Z",
    "updatedAt": "2026-09-30T02:00:00Z"
  }],
  "page": 0,
  "size": 50,
  "totalElements": 1
}
```

新建、重命名、移动返回上述 `items` 中的单个对象。响应不包含存储位置。错误结构为 `{"code":"NAME_CONFLICT","message":"...","fields":{}}`；前端依据 `code` 展示提示。

| 状态与错误码 | 验收场景 |
| --- | --- |
| 400 `INVALID_NAME` | 空名称、分隔符、`.`、`..` 或控制字符 |
| 400 `INVALID_MOVE` | 文件夹移动到自身或后代 |
| 400 `NOT_A_FOLDER` | 指定的自有目标不是文件夹 |
| 401 `UNAUTHORIZED` | 未登录或 Token 失效 |
| 404 `FILE_NOT_FOUND` | 条目不存在，或不在当前用户私有空间 |
| 409 `NAME_CONFLICT` | 同一目录重名，不区分大小写 |

完整字段、名称与错误规则见 [文件管理接口与开发记录](文件管理接口与开发记录.md)。在线接口定义：`/v3/api-docs`；Swagger UI：`/swagger-ui/index.html`。

`java -version` 应显示 21；`mvn test` 应为 `BUILD SUCCESS`，并且测试报告中失败和错误均为 0。默认情况下，`FileIntegrationTest` 会跳过，不能据此声称数据库迁移、唯一约束或并发行为已通过。

真实数据库测试只对**专用测试库**运行。测试会执行 Flyway V1/V2，创建随机测试用户并清理；不要把 `FILE_TEST_DB_URL` 指向共享开发库。先由本机环境注入以下变量，不要在提交、聊天和日志中写实际密码：

```powershell
$env:RUN_FILE_INTEGRATION_TESTS = 'true'

$env:FILE_TEST_DB_PASSWORD = [System.Net.NetworkCredential]::new('', $testDbSecret).Password
mvn '-Dtest=FileIntegrationTest' test
```

验收时确认 `FileIntegrationTest` **8 项执行、0 跳过、0 失败**，并确认专用库中 `flyway_schema_history` 包含 V2、`file_entries` 表存在。测试结束后检查测试库是否留有中断产生的测试数据。真实浏览器认证还需要 Redis 正常运行。

检查点与判定：

| 检查 | 通过条件 |
| --- | --- |
| 迁移 | V1/V2 在专用 MySQL 空库成功执行，JPA `validate` 启动成功 |
| 名称约束 | 同一用户同一目录下 `Docs` 和 `docs` 只能存在一个 |
| 用户隔离 | 用户 B 查询/修改用户 A 条目得到 404 |
| 移动约束 | 文件夹不能移动到自身或后代，数据库目录关系不成环 |
| 容量事务 | 登记失败后不留下文件记录或额外容量使用 |
| 并发 | 同名创建、互相移动、容量竞争、同任务重试均满足集成测试断言 |

## 4. 如何用 HTTP 验收功能

先启动该分支后端，连接专用验收 MySQL 与 Redis。以下 PowerShell 示例会创建临时测试账号和目录，应只在**专用验收库**执行；运行前确认 `$api` 指向该环境。示例不打印 Token。调用失败时先检查响应状态和 `code`，不要继续使用未创建成功的 ID。

```powershell
$api = 'http://localhost:8080/api'
$name = 'handoff_' + [guid]::NewGuid().ToString('N')
$pass = [guid]::NewGuid().ToString('N')
$register = @{ username = $name; password = $pass } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "$api/auth/register" -ContentType 'application/json' -Body $register | Out-Null
$login = Invoke-RestMethod -Method Post -Uri "$api/auth/login" -ContentType 'application/json' -Body $register
$headers = @{ Authorization = "Bearer $($login.token)" }

$rootBefore = Invoke-RestMethod -Method Get -Uri "$api/files?parentId=0&page=0&size=50" -Headers $headers
$a = Invoke-RestMethod -Method Post -Uri "$api/files/folder" -Headers $headers -ContentType 'application/json' -Body (@{ parentId = '0'; name = '验收A' } | ConvertTo-Json)
$b = Invoke-RestMethod -Method Post -Uri "$api/files/folder" -Headers $headers -ContentType 'application/json' -Body (@{ parentId = '0'; name = '验收B' } | ConvertTo-Json)
$child = Invoke-RestMethod -Method Post -Uri "$api/files/folder" -Headers $headers -ContentType 'application/json' -Body (@{ parentId = $a.id; name = '子目录' } | ConvertTo-Json)
$renamed = Invoke-RestMethod -Method Put -Uri "$api/files/$($child.id)/rename" -Headers $headers -ContentType 'application/json' -Body (@{ name = '归档' } | ConvertTo-Json)
$moved = Invoke-RestMethod -Method Put -Uri "$api/files/$($child.id)/move" -Headers $headers -ContentType 'application/json' -Body (@{ targetParentId = $b.id } | ConvertTo-Json)
$aAfter = Invoke-RestMethod -Method Get -Uri "$api/files?parentId=$($a.id)" -Headers $headers
$bAfter = Invoke-RestMethod -Method Get -Uri "$api/files?parentId=$($b.id)" -Headers $headers
if ($aAfter.items.Count -ne 0 -or $bAfter.items.Count -ne 1 -or $bAfter.items[0].name -ne '归档') { throw '目录操作验收失败' }
```

预期：创建返回文件夹 ID；重命名后的 `name` 为“归档”；移动后 A 目录为空，B 目录有一项“归档”。然后用 Swagger UI 或 API 客户端验证：再创建同名目录得 `409 NAME_CONFLICT`；把 B 移进“归档”得 `400 INVALID_MOVE`；第二个用户访问 A/B ID 得 `404 FILE_NOT_FOUND`；无 Token 请求得 401。当前没有删除测试数据的文件 API，临时账号/目录由专用验收库管理员按测试数据策略清理。

## 5. 与前端如何对接和验收

前端使用现有 `frontend/src/api/http.ts`，新增 `files.ts` 请求层。类型和可复制函数见 [文件管理前端对接指南](文件管理前端对接指南.md)。页面接入时要注意现有 `frontend/src/stores/drive.ts` 仍用 localStorage 演示文件：`parentId=null`、小写 `kind`、`size`、`updatedAt` 与新接口的 `"0"`、大写 `entryType`、`sizeBytes`、分页 `items` 不同。需要显式转换或替换数据来源，不能只把请求 URL 改掉。

建议前端按此顺序联调：

1. 用现有登录页取得 Token，查看 Network 面板确认 `/api/files` 请求携带 Bearer Token，且由 Vite `/api` 代理到该分支后端。
2. 用真实列表替换演示数据；进入文件夹时传其字符串 ID，返回上级时传 `"0"`。每次切目录清空旧勾选和分页状态。
3. 接入新建、重命名、移动。成功后重新拉取当前目录；冲突时保留弹窗与用户输入。不要把本地数组更新当成服务端持久化成功。
4. 在两个浏览器账号分别创建目录，刷新页面后检查目录仍存在且互不可见。
5. 检查空目录、分页、网络失败、401、重名、非法移动的提示。首页本地关键词过滤只能作用于已加载页，不能展示为全盘搜索。

浏览器验收通过的条件是：注册/登录后创建 A、B 和 A 的子目录；刷新仍存在；重命名和移动成功；A/B 列表正确更新；另一个账号不可见。上传按钮、下载、回收站和分享不作为本模块验收项。

## 6. 与上传模块如何交接

`FileMetadataService.registerStoredFile(userId, command)` 是内部 Java 服务，**没有**客户端直接调用的“登记文件” HTTP API。上传模块负责从当前认证用户和 FastDFS 上传结果取得可信 userId、实际文件大小和 storageKey，再传入 parentId、文件名、contentType、contentHash、稳定的 ingestKey。登记服务校验目录/容量，写元数据并更新 `users.storage_used`。

同一 ingestKey 同参数重试返回原文件，不重复计费；参数不同返回 `IDEMPOTENCY_CONFLICT`。FastDFS 调用发生在数据库事务外；落库确定失败时由上传模块补偿清理。若结果未知，先用同一命令重试确认，避免误删已经登记的文件。具体签名与字段限制见 [文件管理接口与开发记录](文件管理接口与开发记录.md)。

## 7. 合并前必须解决的分支冲突

写文档时，`dev` 已有另一套 `com.cendodrive.drive` 实现、`V2__create_drive_files.sql` 和 `docs/文件管理接口文档.md`；本分支为 `com.cendodrive.file` 和 `V2__create_file_entries.sql`。两套接口虽然共享 `/api/files` 路径，但根目录表示、列表响应、字段名和数据库模型不同。前端已写的调用不能直接套用本分支响应。

**合并前由团队确定保留哪套模型和协议。** 不能让两个 V2 迁移和两个同路径 Controller 一起进入 `dev`；如果共享库已经执行某个 V2，后续应新增兼容迁移，而不是改写已执行文件。前端、上传模块和文档必须以最终选定的接口为准重新联调。本交接文档描述的是 `Lucky-file-management` 的现有实现，不代表它已经替换 `dev` 的实现。
