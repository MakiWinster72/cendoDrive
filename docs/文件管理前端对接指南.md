# 文件管理前端对接指南

更新日期：2026-09-29。对应分支：`Lucky-file-management`。

状态：后端实现及自动化测试已完成，代码尚待用户分阶段检查与提交；前端页面、真实认证及 FastDFS 上传联调未验收。拿到包含本模块的后端代码并启动后方可联调，不代表共享环境已部署。

范围：接口只访问当前登录用户的私有文件空间。本次不提供角色、分享或其他扩展权限能力；身份认证沿用现有后端机制。

完整字段规则和内部实现见 [文件管理接口与开发记录](文件管理接口与开发记录.md)。本文提供前端接入步骤和可复制的调用示例。

## 1. 环境与认证

- 后端使用 JDK 21、MySQL 8.0.16+、Redis。启动时 Flyway 执行文件表迁移；共享数据库执行前先确认迁移版本。
- 默认后端端口 8080，前端 Vite 默认端口 5173，通过 `/api` 代理后端。
- 复用 `frontend/src/api/http.ts`：已自动添加 Bearer Token，并处理携带 Token 的请求返回 401 时的退出与跳转。
- `http` 默认 baseURL 已是 `/api`，调用路径写 `/files`，不能写 `/api/files`。自定义 VITE_API_BASE_URL 时也应包含 API 前缀，例如 `https://example.com/api`。
- 返回体直接是业务对象，没有 `{code: 200, data: ...}` 包装。
- 后端启动后可访问 `/swagger-ui/index.html`，OpenAPI JSON 位于 `/v3/api-docs`。

## 2. 接口速查

| 功能 | 方法与完整路径 | 请求 | 成功结果 |
| --- | --- | --- | --- |
| 列表 | GET /api/files | query: parentId、page、size | 200 FileListResponse |
| 新建文件夹 | POST /api/files/folder | body: parentId、name | 201 FileEntryResponse |
| 重命名 | PUT /api/files/{id}/rename | body: name | 200 FileEntryResponse |
| 移动 | PUT /api/files/{id}/move | body: targetParentId | 200 FileEntryResponse |

- 根目录 ID 为字符串 `"0"`，所有条目 ID 保持字符串，不转 Number。
- 列表 page 从 0 开始；默认 page=0、size=50，size 范围 1–100。
- 列表仅包含直接子项，文件夹优先、ID 升序；totalElements 是当前目录所有直接子项数量。
- POST 的 parentId、移动的 targetParentId 必填，不能通过省略或 null 表示根目录。
- 时间为 UTC ISO-8601 字符串，前端按需要转为当地时间；sizeBytes 为字节数。
- name 由后端规范化并判重，成功后使用返回名称，不要假定与输入完全一致。
- 不传 userId、storageKey；归属和存储位置由后端管理。

## 3. TypeScript 调用示例

以下为拟放入 `frontend/src/api/files.ts` 的示例，本次文档更新未创建或修改前端源文件。

```ts
import http from './http'

export interface FileEntryResponse {
  id: string
  parentId: string
  name: string
  entryType: 'FILE' | 'FOLDER'
  sizeBytes: number
  contentType: string | null
  createdAt: string
  updatedAt: string
}

export interface FileListResponse {
  parentId: string
  items: FileEntryResponse[]
  page: number
  size: number
  totalElements: number
}

export async function listFiles(parentId = '0', page = 0, size = 50) {
  const { data } = await http.get<FileListResponse>('/files', {
    params: { parentId, page, size },
  })
  return data
}

export async function createFolder(parentId: string, name: string) {
  const { data } = await http.post<FileEntryResponse>('/files/folder', { parentId, name })
  return data
}

export async function renameFile(id: string, name: string) {
  const { data } = await http.put<FileEntryResponse>(`/files/${encodeURIComponent(id)}/rename`, { name })
  return data
}

export async function moveFile(id: string, targetParentId: string) {
  const { data } = await http.put<FileEntryResponse>(`/files/${encodeURIComponent(id)}/move`, { targetParentId })
  return data
}
```

响应示例：

```json
{
  "parentId": "0",
  "items": [{
    "id": "101",
    "parentId": "0",
    "name": "工作资料",
    "entryType": "FOLDER",
    "sizeBytes": 0,
    "contentType": null,
    "createdAt": "2026-09-29T03:00:00Z",
    "updatedAt": "2026-09-29T03:00:00Z"
  }],
  "page": 0,
  "size": 50,
  "totalElements": 1
}
```

新建、重命名和移动的响应为 items 中的单个条目结构。

## 4. 页面接入建议

1. 登录后读取根目录，替换 HomeView 的静态数组；列表与网格共用返回数据。文件夹大小展示为 `—`。
2. 点击文件夹后以其 id 重新请求列表，将 page 重置为 0，清空旧勾选。
3. 面包屑暂由前端维护导航路径；当前没有祖先链或条目详情接口，刷新时可回根目录，不应假设可通过任意目录 ID 重建路径。
4. 新建、重命名和移动成功后重新读取当前目录；若当前页因移动变空且 page>0，则退一页再查询。
5. 移动选择器通过同一列表接口获取目录。列表同时含文件，过滤当前页 FILE 后并不代表已拿到所有文件夹，应保留分页加载。
6. 根目录可作为移动目标；前端可屏蔽自己，但后代判断和最终权限仍以后端结果为准。
7. 切换目录时取消旧请求或使用请求序号，避免较慢的旧请求覆盖新目录数据。
8. 请求中禁用重复提交。新建文件夹没有请求级幂等键，网络超时后先刷新确认是否已创建，不能盲目重试或自动追加名称。

当前不提供上传、下载、删除、分享、服务端搜索、自定义排序或批量操作接口。首页现有本地关键词过滤只能过滤当前已加载页，不能标注为全盘搜索。容量展示可取 `/api/user/me` 的 storageUsed/storageLimit，不使用首页静态数值。

## 5. 错误处理

业务错误格式：

```json
{"code":"NAME_CONFLICT","message":"Name already exists in this folder","fields":{}}
```

按 code 映射中文提示，不复用 authErrorMessage 的“409 用户名已存在”逻辑，也不要依赖英文 message 判断类型。

| HTTP / code | 前端建议 |
| --- | --- |
| 400 INVALID_NAME | 保留输入，提示名称不合法 |
| 400 INVALID_INPUT / INVALID_JSON | 提示参数错误；fields 存在时对应展示 |
| 400 NOT_A_FOLDER | 刷新目标目录选择器 |
| 400 INVALID_MOVE | 提示不能移动到自身或子目录 |
| 401 UNAUTHORIZED | 由现有认证拦截器清理会话并跳转 |
| 404 FILE_NOT_FOUND | 提示条目不存在或不可访问，刷新列表 |
| 409 NAME_CONFLICT | 保持弹窗，提示目标目录已有同名条目 |
| 网络超时 / 无响应 | 提示连接失败；写操作先查询确认结果 |
| 500 或其他服务端错误 | 提示稍后重试，不假设修改已经成功 |

容量不足和上传任务幂等冲突属于后续上传流程，完整错误码见主接口文档。

## 6. 联调验收清单（待实际执行）

- [ ] 用户 A 创建根目录文件夹、子文件夹；刷新后仍存在。
- [ ] 重命名生效；同目录不同大小写的同名创建被拒绝。
- [ ] 移动后原目录消失、目标目录出现；移回根目录成功。
- [ ] 移动到自己/后代被拒绝，同目录移动正常成功。
- [ ] 用户 B 不能查询或修改 A 的目录，收到 404。
- [ ] 分页、空列表、加载中、错误提示、过期登录行为正常。
- [ ] 真正跨域部署时 PUT 的 OPTIONS 预检通过；同源代理无需配置额外 CORS。

前端若需要树形目录、详情或批量能力，先约定新增契约，不假定本次接口已提供。
